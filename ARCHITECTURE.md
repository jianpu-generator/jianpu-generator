# Architecture

## Pipeline Overview

```
source (&str)
  → [parser]              → ParsedDocument
                             Raw event stream: notes, rests, chords, directives,
                             lyrics syllables per measure. No note measure grouping yet.
  → [grouper]             → Score
                             Notes grouped into measures; lyrics paired to each
                             measure's lyric slots (tie-aware);
                             parts organized into MultiPartMeasure slices;
                             optional `# sequence` section resolved into
                             Score.sequence spans.
  → [compiler]            → CompileResult
                             Logical grid: each note/rest assigned to a column,
                             underlines computed, slur spans recorded.
  → [consolidator]        → CompileResult
                             Mixed notes+lyrics rows split; duplicate rows with
                             identical content suppressed per measure.
  → [grid_layout]         → Vec<GridPage>
                             Grid elements placed into rows with heights and column
                             counts; rows wrapped across pages; slur arcs resolved
                             to same-system or cross-system variants.
  → [coordinate_resolver] → Vec<AbsolutePage>
                             Every element assigned absolute x/y coordinates in
                             points; grid geometry collapsed to flat element list.
  → [renderer]            → Vec<SvgDocument>
                             SVG primitives (Text, Line, Circle, Path) produced
                             for each absolute element.
  → [serializer]          → Vec<String>
                             SVG strings, one per page, ready to write to disk.
```

## Layer Details

### Parser
- Module: `src/parser/`
- Entry: `parser::parse(source: &str, filename: &str) -> Result<ParsedDocument, IrrecoverableError>`
- Key types: `ParsedDocument` (also carries `sequence: Option<SequenceSection>` and `sequence_parse_errors: Vec<RecoverableError>` from the optional `# sequence` section — see **Sequence resolution** in the glossary; also carries `group: Option<GroupSection>` and `group_parse_errors: Vec<RecoverableError>` from the optional `# groups` section; also carries `abbreviation_references: Vec<AbbreviationReference>` — every `[Abbrev]` key-prefix reference found in `# score`, in file order, each `{ abbreviation, span }` with `span` covering just the trimmed abbreviation text (excluding brackets/whitespace) — see **Rename-symbol support**), `ParsedTimedTrack`, `ParsedScore`, `ScoreEvent` (includes `PercussionHit(ParsedPercussionHit)`; `LabelChange(String)`'s `Spanned` wrapper carries a span narrowed to just the quoted label text, not the whole `label="..."` token), `ParsedNote` (carries `Accidental` for melody notes; tie intent via `tie_to_next_span: Option<Span>` with `tie_to_next()` accessor), `ParsedRest`, `ParsedChordNote` (also carries `Accidental` and `tie_to_next_span`), `ParsedPercussionHit` (`ParsedNote` minus pitch/accidental — carries duration, dotted, group membership, tie/slur fields), `ParsedMetadata`, `JianPuPitch`, `Accidental` (`Sharp`/`Flat`/`Natural`; applies to both melody notes and chord notes), `Syllable`, `Soundfont` (vocal/piano/string; selects MIDI channel+program — on a `PartKind::Percussion` part, the number is instead a fixed GM percussion key rather than a GM program number, and is not validated against the melodic instrument catalog), `PartDecl` (carries `soundfont`, `volume`, `octave_offset`, `kind: PartKind`, `abbreviation_span: Span` — the abbreviation token's own byte span on its declaration line, used by rename-symbol — `PartKind::Percussion` reuses `&[ScoreLineRole::Notes]` for its score line roles), `SequenceSection` (parsed from `src/parser/sequence_parser.rs`'s `parse_sequence(content, offset) -> (Option<SequenceSection>, Vec<RecoverableError>)` — a comma-separated list of section-label references, each a `SequenceEntry { label, label_span, omit_parts, omit_part_spans, span }` where `omit_parts` comes from an optional `(-abbrev -abbrev ...)` suffix naming part/group abbreviations to omit from that occurrence's playback, e.g. `Chorus(-S -A2)`, and `label_span`/`omit_part_spans` are the byte spans of just the label text and each omitted abbreviation (used by rename-symbol) — see **Sequence resolution** in the glossary), `GroupSection`/`GroupDef` (parsed by `src/parser/group_parser.rs`'s `parse_group(content, offset) -> (Option<GroupSection>, Vec<RecoverableError>)` — carries `abbreviation_span`/`member_spans: Vec<Span>` alongside `abbreviation`/`members`, for rename-symbol — see **Group** in the glossary). `# groups` is parsed before `# score` so `group_parser::resolve_and_validate_groups(group_section, declarations) -> (Vec<ResolvedGroup>, Vec<RecoverableError>)` can run first; its `ResolvedGroup { abbreviation, members }` list (each member a concrete, transitively-resolved part abbreviation, all sharing one `PartKind`) is threaded into `score::interleaved_parser::parse(content, base_offset, declarations, resolved_groups) -> ParseResult` and on into `desugar::desugar_groups(groups, declarations, resolved_groups, base_offset)`, which lets a `[GroupAbbrev]` key prefix in `# score` broadcast a line to every resolved member — see **Group** in the glossary.

### Grouper
- Module: `src/grouper/`
- Entry: `grouper::group(doc: ParsedDocument) -> Result<Score, IrrecoverableError>`
- Key types: `Score` (carries `sequence: Option<Vec<SequenceSpan>>`, resolved by `resolve_sequence()` in `src/grouper/sequence_resolution.rs` — see **Sequence resolution** in the glossary), `SequenceSpan` (`label`, `start`, `end`, `omit_parts`, `omit_parts_display`: an inclusive resolved measure-index range for one `# sequence` entry, plus that occurrence's part abbreviations to omit from MIDI/WAV playback — `omit_parts` expands any group abbreviation in the entry's `(-abbrev ...)` suffix to its member parts (used for filtering), while `omit_parts_display` keeps a group abbreviation unexpanded (used for the "Sequence: ..." summary line, which shows the group's own label rather than its members) — see **Sequence resolution**), `MultiPartMeasure` (carries `bpm`/`key`/`time_signature`/`label` (all non-persisting on this type — see below) plus the always-resolved, persisting `merge_duplicate_measures_across_parts`/`hide_resting_parts` booleans, and the navigation markers `dc_al_coda`/`to_coda`/`coda` (D.C. al Coda), `segno`/`ds_al_coda` (D.S. al Coda), `dc_al_fine`/`fine` (D.C. al Fine), and `segno`/`ds_al_fine`/`fine` (D.S. al Fine), all non-persisting — see **Navigation expansion** in the glossary), `PartRow` (Timed), `PartSlice` (carries `soundfont`, `volume`, `octave_offset`, `group_provenance: Option<String>` — the `[GroupAbbrev]` broadcast that produced this measure's content, when not overridden; see **Group** in the glossary), `Notes`, `NoteEvent` (includes `Percussion(GroupedPercussionHit)`), `GroupedNote`, `GroupedRest`, `GroupedChordNote` (`GroupedNote`/`GroupedChordNote` use `tie_to_next_span` + `tie_to_next()` accessor), `GroupedPercussionHit` (mirrors `GroupedNote` minus pitch/accidental/octave, plus `event_span`; `slur_key()` returns the inert `SlurKey::Rest` sentinel since hits have no pitch to differentiate slur arcs by), `GroupedMeasure` (intermediate: notes + `paired_lyrics: Vec<Vec<Syllable>>` — one entry per verse, tie-paired against the notes independently per verse — plus `group_provenance: Option<String>` carried from `ParsedTimedTrack.per_measure_group_provenance`). `PartSlice.lyrics: Vec<Lyrics>` carries the same one-entry-per-verse shape through to the compiler; a part's verse count is per-measure (see **Lyrics line**/**Verse** in the glossary).
- `merge_duplicate_measures_across_parts`/`hide_resting_parts` on `MultiPartMeasure` are resolved (not `Option`) by `DirectiveGrouper` (`src/grouper/directive_grouper.rs`): seeded from `Metadata::merge_duplicate_measures_across_parts`/`Metadata::hide_resting_parts` (the `# metadata` default) and overridden from a given measure onward by a `merge_duplicate_measures_across_parts=`/`hide_resting_parts=` directive line, persisting like `bpm`/`key`/`time` until the next override — unlike those three, they carry the fully resolved value on every measure rather than `Some` only where changed, since downstream consumers (`compiler::compile_measure`, `consolidator::consolidate_block`) need a plain value per call and have no rendering reason to know whether it just changed.

### Compiler
- Module: `src/compiler/`
- Entry: `compiler::compile(score: &Score) -> CompileResult`
- Key types: `CompileResult`, `MeasureBlock` (carries `represents_measures: usize`, the number of original source measures the block stands in for — `1` normally, `> 1` when a rest run was folded; consumers that walk blocks and assume one block == one measure must advance their measure counter by this field, not by `1`; also carries `merge_duplicate_measures_across_parts: bool`, copied from the originating measure's `MultiPartMeasure::merge_duplicate_measures_across_parts` — see Consolidator below), `MeasureRow` (carries `group_provenance: Option<String>`, copied from the source part's `PartSlice.group_provenance`), `ColumnElement` (carries `note_id: Option<usize>` — see **Note identity** in the glossary), `ElementContent` (includes `PercussionHit`, threaded through `GridContent`/`PostArcGridContent`/`AbsoluteContent`/`SvgVariant::PercussionHit` and rendered centered via `render_percussion_hit`; also includes `MultiMeasureRest { count }`, threaded the same way through `GridContent`/`PostArcGridContent`/`AbsoluteContent`/`SvgVariant::MultiMeasureRest` and rendered via `render_multi_measure_rest` — see **Multi-measure rest** in the glossary), `SlurSpan`, `ArcKind`, `Decoration`
- `compiler::visible_part_indices(measure: &MultiPartMeasure) -> Vec<usize>` resolves which of `measure.parts` are actually compiled/sounded for that measure (an all-rest part is hidden when `hide_resting_parts` is in effect and at least one other part has real content). `compile_measure` uses it directly; `midi::timing::note_timings_seconds` (see **Note identity**) also walks `measure.parts` filtered through this same function, so its per-part `note_id` counters advance in lockstep with `ColumnElement::note_id`.
- `compile()`'s main loop still produces one block per source measure (preserving per-measure `cross_states`/`slur_spans`/bar-number bookkeeping); a post-pass `merge_rest_runs()` then folds maximal runs of 2+ eligible all-rest measures (see **Multi-measure rest**) into single blocks. Grid layout stays unaware of this folding — it only ever sees already-resolved blocks and lays out whatever `ElementContent`/`GridContent` variant it's given.
- `hide_resting_parts` (from `MultiPartMeasure::hide_resting_parts`, resolved per measure — see Grouper above) gates `compile_measure`'s omission of an all-rest part's row when at least one other part in the same measure has real content; when `false`, every part's row is rendered even if it's all rests.
- A change in `merge_duplicate_measures_across_parts`/`hide_resting_parts` between two otherwise-collapsible measures forces a new run boundary in `merge_rest_runs()`, the same way a `label` does, since a merged block carries one resolved setting pair (taken from the run's first measure) for every measure it stands in for.

### Consolidator
- Module: `src/consolidator/`
- Entry: `consolidator::consolidate(result: CompileResult) -> CompileResult`
- Splits mixed `notes lyrics` rows into one notes row plus one lyrics row per verse (`ElementContent::Lyric { text, verse }` groups by `verse`), each verse's row getting a distinct `RowId` (`"{part}-lyrics-{verse}"`), then removes duplicate rows within each measure when their `elements` are identical (labels and ids are not compared). `slur_spans` are passed through unchanged.
- `merge_duplicate_measures_across_parts` (read per block from `MeasureBlock::merge_duplicate_measures_across_parts`, resolved per measure by the grouper — see Grouper above) gates only merges between rows with different `source_part_index`; rows from the same part still merge regardless.
- Because each verse gets its own `RowId`, a part's verse count changing between two measures changes that measure's row-id list, so `grid_layout::layout::pack_into_systems`'s existing row-identity check (see **System**) already forces a new system at that boundary — no separate verse-count check is needed.
- When rows merge, `merge_labels()` sets the surviving row's label to the shared group abbreviation when every merged row's `group_provenance` traces to the same `[GroupAbbrev]` broadcast (see **Group** in the glossary); otherwise it falls back to the space-joined concatenation of each source row's original label (its part abbreviation), and the surviving row's `group_provenance` is cleared to `None` so a later merge in the same pass can't mistake a partially-diverged cluster for a fully in-group one.

### Grid Layout
- Module: `src/grid_layout/`
- Entry: `grid_layout::layout(result: &CompileResult, config: &RenderConfig, header: &Header, width_pt: f32, height_pt: f32) -> Vec<GridPage>`
- Key types: `GridPage` (carries `note_highlight_targets: Vec<NoteHighlightTarget>` alongside `measure_highlights`/`error_highlights`/`measure_click_targets` — see **Note identity**), `GridRow`, `GridElement`, `GridContent`, `HAlign`, `VAlign`, `ColumnGeometry`, `MeasureColumnLayout`, `NoteHighlightTarget` (`row_start`/`row_end`/`column_start`/`column_end` like `MeasureHighlight`, plus `source_part_index`/`note_id`)
- `grid_layout::highlight::compute_all_note_highlight_targets` (mirrors `compute_all_measure_click_targets`'s page/system/block traversal) groups each `MeasureRow`'s elements by `note_id` per block and emits one `NoteHighlightTarget` per contiguous run, scoped to that one part's own sub-rows (`part_row_ranges`) rather than the whole system's row range `MeasureHighlight` uses. A tied note split across a system/line break, or a repeated measure position with no navigation-aware remapping, can legitimately produce more than one `NoteHighlightTarget` sharing the same `(source_part_index, note_id)` — the frontend highlights all of them together.
- `config.hide_system_dividers` (from `Metadata::hide_system_dividers`, `# metadata` field `hide_system_dividers`, default `no`) gates `layout::build_page_rows`'s insertion of the full-width `GridContent::HorizontalLine` separator row between systems, and the corresponding gap in `layout()`'s page-break height accounting; when `true`, no divider row or gap is inserted between systems.
- `GridRow.has_label_region` (`true` for system rows built by `expand::expand_system_to_rows`/`layout_decoration::make_decoration_row`, `false` for header/footer/separator rows) marks which rows reserve `LABEL_COLS` columns for the part label. `GridRow::column_geometry(usable_width_pt, label_width_pt) -> ColumnGeometry` uses this flag to give the label region a fixed pixel width (`config.part_label_width_pt`) independent of that row's own `column_count`, while the remaining columns still split the rest of the width evenly — this is what keeps the part-label column the same rendered width across systems of differing musical density, rather than the old uniform `usable_width_pt / column_count` division which made the label's width vary with each system's content.
- `GridRow.measure_layout: Vec<MeasureColumnLayout>` (one entry per measure in the row's system, shared by every row of that system — built once by `layout::build_measure_column_layout` and threaded into `expand::expand_system_to_rows`/`layout_decoration::make_decoration_row`) records each measure's `start_col`, `col_count` (`block_column_width`), and `weight` (`layout::measure_spacing_weight`, the max note/rest/dash/percussion-hit/chord-symbol count across the measure's part rows, so density scales with the busiest part rather than the part count; a collapsed `MultiMeasureRest` gets a fixed weight of `MULTI_MEASURE_REST_WIDTH` instead). `column_geometry` uses it to split the music region into one `ColumnSegment` per measure, sized by `MIN_MEASURE_WIDTH_PT` (a fixed floor) plus a share of the remaining width proportional to `weight` — so denser measures render wider and sparser ones narrower, while columns within one measure stay uniform. When `measure_layout` is empty (headers/footers/separators, or a row with no system), `column_geometry` falls back to the old single-scalar uniform division. Because `x_start`/`col_width` become piecewise-linear across segments, span-width consumers (`coordinate_resolver::resolve`'s arc/underline formulas, `coordinate_resolver::highlights`'s highlight/click-box formulas) must compute a span's width as `x_start(end) - x_start(start)` rather than `col_width(start) * span`, so a span crossing measures of different width still gets its true pixel extent; `ColumnGeometry::column_center(col) -> f32` (`x_start(col) + col_width(col) * 0.5`) is the shared helper for arc/underline endpoints.

### Coordinate Resolver
- Module: `src/coordinate_resolver/`
- Entry: `coordinate_resolver::resolve(pages: &[GridPage], note_number_width: f32, part_label_width_pt: f32, lyric_font_sizes: LyricFontSizes) -> Vec<AbsolutePage>`
- Key types: `AbsolutePage`, `AbsoluteElement`, `AbsoluteContent` (includes `NoteHighlightTarget { width, height, source_part_index, note_id }`, resolved by `coordinate_resolver::highlights::resolve_note_highlight_target` — see **Note identity**), `PostArcGridContent`
- `PostArcGridContent`: `GridContent` minus the three arc variants (`TieOrSlur`, `TieOrSlurTail`, `TieOrSlurHead`); arc variants are resolved before `grid_to_absolute` and must not appear in the coordinate-resolver layer.

### Renderer
- Module: `src/renderer/`
- Entry: `renderer::new_renderer::render_new(pages: &[AbsolutePage], config: &RenderConfig) -> Vec<SvgDocument>`
- Key types: `SvgDocument`, `SvgElement`, `SvgKind` (includes `NoteHighlightRect { width, height }`, rendered `fill="transparent"` by the serializer/preview and toggled at playback time by the frontend — see **Note identity**), `SvgVariant`, `TransparentRectRole`, `Tag` (includes `Note { source_part_index, note_id }`, wrapping a `NoteHighlightRect` in a `Group`, mirroring `Tag::Measure`'s wrap of a `MeasureClickTarget`)
- `SvgElement.variant` is `Option<SvgVariant>`: `None` for group wrappers and highlight rects; `Some(...)` for musical/export drawable primitives
- `SvgKind::TransparentRect` carries a `role: TransparentRectRole` for CSS hover targets (`data-variant` in serializer/preview); roles are `MeasureClickTarget`, `SectionLabelBackground`, and `SectionLabelClickTarget`
- `config.directive_row_offset` (from `Metadata::directive_row_offset`, `# metadata` field `directive_row_offset`, an `Offset { x, y }` in points, default `(0, 0)`) is applied unconditionally by `render_directive_line` (`src/renderer/new_renderer/directive_line.rs`) to every directive row — the bar-number/section-label/key/bpm/time-signature/navigation-marker line above the staff — shifting all of that row's elements (bar-number text, key/bpm/time-signature/navigation-marker text, optional label background rect, optional independent label text, optional Segno glyph) together, after `coordinate_resolver` has already resolved their absolute position. `AbsoluteContent::DirectiveLine` renders the bar number, section label, and the key/bpm/time-signature/navigation-marker run as three independently-positioned elements rather than one shared text run, each with its x position precomputed in `coordinate_resolver::content_conversion` from real glyph-advance measurements (`src/font_metrics.rs`, pinned against the same font embedded for PDF export) instead of a character-bucket heuristic: `bar_number: Option<TextSpan>` is pinned to the line's start (offset 0); `label_x_offset: f32` positions the section label past the bar number (plus a fixed gap) when one precedes it, zero otherwise; `spans_x_offset: f32` positions the remaining spans past whichever of `bar_number`/`label` is present, so none of the three overlap regardless of their measured widths. When a label is present, its `<g data-tag="section-label">` group also carries an invisible `SectionLabelClickTarget` rect spanning the whole directive line (bar number through trailing spans/Segno) as its first child — without it, the group's actual clickable area would be only the union of its children's painted pixels, which leaves an unpainted gap (and therefore a dead click zone, despite `cursor: pointer` covering it) whenever a directive line has a label but no trailing spans (e.g. a bare `label="B"` line). The `# sequence` summary header line renders through the same function but is explicitly excluded (`AbsoluteContent::DirectiveLine.apply_row_offset = false`). It never reaches `grid_layout` or `coordinate_resolver` — those layers are unaware of it.

### Serializer
- Module: `src/serializer/`
- Entry: `serializer::serialize(docs: &[SvgDocument], source: Option<&str>) -> Vec<String>`
- When `source` is `Some`, each emitted `<svg>` gets a base64-encoded, non-rendering `<metadata id="jianpu-source">` child holding the original `.jianpu` text, so a lost source file can be recovered from a previously exported SVG. `source_embed::extract_embedded_source(svg: &str) -> Option<String>` (`src/source_embed.rs`) reverses this. Only call sites with source in scope (e.g. `render_svgs_from_source_filtered_with_lyrics`, `render_svgs_with_highlight_range`) pass `Some`; the `Score`-only `render_svgs` path passes `None` and emits no metadata tag.
- PDF export (`pdf::write_pdf(svgs: &[String], fonts: &PdfFonts, source: Option<&str>) -> Result<Vec<u8>, IrrecoverableError>`, `src/pdf.rs`) can't reuse this `<metadata>` embedding — `usvg` (which parses each page's SVG string before `svg2pdf` conversion) strips `<metadata>` tags. Instead, when `source` is `Some`, it base64-encodes the source into a custom `/JianpuSource` key in the PDF's `/Info` dictionary via `pdf_writer`'s `DocumentInfo`. `source_embed::extract_embedded_source_from_pdf(pdf: &[u8]) -> Option<String>` reverses this by string-searching the (uncompressed) `/Info` dictionary bytes. `write_pdf_from_source_filtered_with_lyrics` and the CLI's non-split `generate_pdf` pass `Some`; `write_split_pdfs_from_source` (split-track export) passes `None`, matching split-track SVG export's `None` for the same reason.

## Glossary

| Term | Definition |
|------|-----------|
| **System** | A horizontal row of measures that fit on one line of a page. The grid layout wraps measures into systems based on column count and page width. |
| **Measure** | One bar of music. The score is a flat sequence of `MultiPartMeasure`s. |
| **Part** | A single instrument or voice track (e.g. soprano, bass). Declared in `[parts]`. |
| **Part Slice** | One part's notes and lyrics (one or more verses) for a single measure (`PartSlice`). |
| **Ditto** | A measure where every input line was `"`, meaning it repeats the previous measure. Rendered as blank; audio output still uses the resolved content. |
| **Column** | A logical horizontal slot in the compiler's grid. Each beat occupies one or more columns. |
| **Quarter-beat** | The smallest time unit used for duration arithmetic. A standard quarter note = 4 quarter-beats. |
| **Underline** | A horizontal line drawn below note heads to indicate duration subdivision. `level=0` = half-beat, `level=1` = quarter-beat. |
| **Octave Dot** | A dot drawn above or below a note head to shift its octave. Count = `octave.abs()`. |
| **Note Dash** | A visual `-` drawn after a note head for each extra beat of duration. |
| **Lyrics line** | One plain-text line per measure per `notes lyrics` part, tokenised into syllables and stored per measure (not as a global pool). Consecutive lyrics lines after the notes line are separate verses — see **Verse**. |
| **Verse** | One of a `notes+lyrics` part's lyric lines for a measure, 0-indexed. The number of verses is per-measure (declared implicitly by how many consecutive `[Part]` lyric lines follow the notes line) and can differ between measures for the same part; each verse is tie-paired against the notes independently and rendered as its own row. A verse-count change between two measures of the same part forces a system break (see **System**). |
| **Arc Span** | The full logical extent of one slur or tie arc, possibly crossing measure or system boundaries (`SlurSpan`). Carries `ArcKind` to distinguish ties from slurs. |
| **ArcKind** | Discriminant on `SlurSpan`: `Slur` (from `(…)` groups) or `Tie` (from `~`). Both render as arcs; the kind is available for future visual distinction. |
| **Decoration** | Measure-level metadata attached to a `MeasureBlock`: BPM, time signature, section label, bar number, D.C. al Coda navigation markers (`dc_al_coda`/`to_coda`/`coda`), D.S. al Coda navigation markers (`segno`/`ds_al_coda`, reusing `to_coda`/`coda`), D.C. al Fine navigation markers (`dc_al_fine`/`fine`), D.S. al Fine navigation markers (`segno`/`ds_al_fine`, reusing `fine`). |
| **Row Label** | The part name displayed at the left margin of a system row, in a fixed-width column (`Metadata::part_label_width_pt`, `# metadata` field `part_label_width_pt`, default `40` points) shared by every system in the score regardless of that system's musical density — see **Grid Layout**'s `ColumnGeometry`. |
| **RowId** | A unique string identifier for a compiler row, used to correlate rows across layout stages. |
| **Measure Start Time** | The elapsed-seconds offset of a measure boundary within a score's audio rendering, computed from cumulative MIDI ticks and any BPM changes (`midi::measure_start_times_seconds`). Used to sync a playback-position UI element (a "playhead") against a `<audio>` element's `currentTime`. |
| **Note identity** | `(source_part_index, note_id)`: the identity key shared by a written note/rest's `ColumnElement`/`GridElement`/rendered `data-tag="note"` group and its MIDI/WAV timing, so the SVG preview can highlight whichever note is currently sounding, independently per part. `source_part_index` is the same raw `measure.parts` index `MeasureRow::source_part_index` already uses. `note_id` is a running counter per part, incrementing once per `NoteEvent` consumed from that part's `notes.events` — assigned by the compiler (`compiler::part_slice`, threaded per-part across measures via `PartCrossState::next_note_id`) when building `ColumnElement`s, and independently re-derived by `midi::timing::note_timings_seconds(score: &Score) -> Result<Vec<NoteTiming>, IrrecoverableError>` (`NoteTiming { source_part_index, note_id, start_s, end_s }`) when computing MIDI-tick-based timings — both walk `score.measures[i].parts[j].notes.events` in the same raw order (via `compiler::visible_part_indices`), independent of the MIDI writer's channel-pooling (`parts_matching`/`part_index_to_midi_channel`), so the two assignments agree. A tie continuation (`tie_to_next()`) reuses the id of the note it continues from, on both sides, rather than allocating a fresh one — mirroring the MIDI writer's own merge of a tied note into a single NoteOn/NoteOff pair — so a tie crossing a measure or system boundary is one `note_id` with one merged `NoteTiming` (extended `end_s`) but can still resolve to more than one `NoteHighlightTarget` (see **Grid Layout**) if it crosses a line break. `audio_source::note_timings_from_source` (the `lib.rs`-level entry point, exported as WASM `list_note_timings`) deliberately does **not** run the score through **Navigation expansion** first, unlike `measure_start_times_from_source`: doing so would reassign `note_id`s along the expanded/repeated timeline instead of the written one. This makes no difference for a score with no D.C./D.S./`# sequence` markers (expansion is then a no-op); for one that repeats, note highlighting is only accurate through the first pass. The frontend (`components/noteHighlightPosition.ts`, `components/useNoteHighlight.ts`) binary-searches each part's sorted `NoteTiming`s to find the active note at the current playback time and toggles the `fill` of that `(source_part_index, note_id)`'s `NoteHighlightRect`(s) (see **Renderer**), replacing the old measure-level playhead built from **Measure Start Time**. `midi::timing::note_timings_seconds_for_range(score: &Score, start_pos: usize, end_pos: usize) -> Result<Vec<NoteTiming>, IrrecoverableError>` is the range-scoped counterpart backing `audio_source::note_timings_for_range_from_source`/WASM `list_note_timings_for_range`, used when playing a clip via `write_wav_for_measure_range_from_source` (e.g. "play from this measure") instead of the whole score: `start_s`/`end_s` are rebased to the *clip*'s own start (matching `measure_start_times_seconds_for_range`), but `note_id`s are still resolved via `build_written_note_id_lookup`/`compile(score).blocks` computed once over the passed-in `score`, which callers must pass as the *original, unexpanded* written score (unlike `measure_start_times_seconds_for_range`, whose `score` parameter is already the expanded score) — `note_timings_seconds_for_range` re-derives the expanded/playback-order timeline itself via `expand_navigation_with_note_positions` so `start_pos`/`end_pos` (already-resolved playback positions, not raw written indices — see **Navigation expansion**) line up with both the tick/tempo accounting and the written-score `note_id`s. |
| **GM percussion key** | A General MIDI drum-kit key number (0–127) identifying a specific unpitched drum sample (e.g. `38` = Acoustic Snare, `36` = Bass Drum 1) played on the shared GM percussion channel (MIDI channel 9). Used as the `Soundfont` number on `PartKind::Percussion` parts instead of a melodic GM program number. |
| **Multi-measure rest** | A run of 2 or more consecutive source measures, each all-rest on every currently-visible part (post track-filter) and carrying no nav marker, time signature/BPM/key change, or diagnostic, collapsed by the compiler's `merge_rest_runs()` into a single `MeasureBlock` (`represents_measures = N`) with one `ElementContent::MultiMeasureRest { count: N }` per row. Rendered as one wide bar with short end ticks and the count `N` printed above it, instead of `N` separate rest measures. A `label` does not disqualify a measure from the run, but it does force a new run to start there — the label can never be absorbed into a run that began before it, and is preserved on the merged block it heads (via that measure's `Decoration`) so it stays visible. A change in `merge_duplicate_measures_across_parts`/`hide_resting_parts` from the previous measure has the same effect: it forces a new run to start, since a merged block carries only one resolved setting pair. A lone eligible measure (run length 1) is left uncollapsed. |
| **Navigation expansion** | `midi::expand_navigation(score: &Score) -> Result<Score, IrrecoverableError>`, a `Score -> Score` pass applied on the whole-score MIDI/WAV export path (after `apply_track_filter`, before `midi::write_midi`) and on `measure_start_times_from_source`. Rebuilds `measures` by index to reflect exactly one of four marker schemes (mixing them is an error): the `dcalcoda`/`tocoda`/`coda` markers (play from the start through the `dcalcoda` measure, restart from the start through the `tocoda` measure, then jump to the `coda` measure through the literal end); the `segno`/`dsalcoda`/`tocoda`/`coda` markers (same, but pass 2 restarts from the `segno` measure instead of the start); the `dcalfine`/`fine` markers (play from the start through the `dcalfine` measure, then restart from the start through the `fine` measure and stop, with no coda section); or the `segno`/`dsalfine`/`fine` markers (same, but pass 2 restarts from the `segno` measure instead of the start). Identity when no markers are present. Thin wrapper over `midi::expand_navigation_with_origins(score: &Score) -> Result<(Score, Vec<usize>), IrrecoverableError>`, which additionally returns a same-length `Vec<usize>` mapping each expanded measure back to its index in the written `Score`. When `score.sequence` is `Some` (see **Sequence resolution**), `expand_navigation_with_origins` takes a separate branch instead of applying any marker scheme: it concatenates each `SequenceSpan`'s `start..=end` measure range, in `# sequence` order, pairing each measure index with that span's `omit_parts`, and builds the expanded `Score`/origins via a shared `build_expanded(score, idx: Vec<(usize, &[String])>)` helper (also used by the marker-path tail, with an empty `omit_parts` slice for every position). For each position, `build_expanded` clones the written measure and retains only parts whose `PartRow::name()` (the part's abbreviation) is absent from that position's `omit_parts`, so a `# sequence` entry's `(-abbrev ...)` suffix (see **Sequence resolution**) silences only that specific occurrence's playback, leaving the written score and other occurrences of the same label untouched. `midi::earliest_playback_position(origins: &[usize], written_index: usize, min_pos: usize) -> Option<usize>` finds the smallest expanded position `>= min_pos` whose origin equals `written_index`; `midi::expand_for_measure`/`midi::expand_for_measure_range` use it to translate written measure-index/range requests into playback-order positions, and are called from `lib.rs` for the four measure-index entry points (`write_wav_for_measure_from_source`, `write_wav_for_measure_range_from_source`, `measure_start_times_from_source`, `measure_start_times_for_range_from_source`), falling back to the written index/range when a measure has no reachable playback position (e.g. it lies strictly between the `dcalcoda`/`dsalcoda` measure and the `coda` measure). `expand_for_measure_range`'s end position uses a *last*-occurrence scan only when `end_index` is the score's literal last written measure (the "play from current measure to the end" case); otherwise it uses the same earliest-occurrence search as `start_index`, so selecting an exact written range (e.g. "play current measure", where `start == end`) doesn't overrun into a later repeat/jump pass. `audio_source::note_timings_for_range_from_source` also calls `expand_for_measure_range`, but — unlike the other four callers — only keeps the resolved `(start_pos, end_pos)` positions, discarding the expanded `Score` it returns, since `midi::timing::note_timings_seconds_for_range` (see **Note identity**) needs the *original* written score for `note_id` lookup and re-derives the expanded timeline itself. SVG/PDF export never calls any of this — those always render measures in written order. |
| **Group** | A named alias for a specific set of part abbreviations, declared in the optional `# groups` section (`<display-name> [<abbreviation>] = <members>`), parsed into `GroupSection`/`GroupDef` by `group_parser::parse_group()`. Has three independent effects. Legend: `part_info::list_groups_from_source()` re-parses the source into `GroupInfo { abbreviation, display_name, members }` entries, `lib::filter_group_list()` drops a group when a track filter (`enabled_tracks`) excludes all of its `members`, and `build_header()` appends each surviving group (whose `abbreviation != display_name`) to `Header.part_list` alongside `PartInfo` entries, so it renders in the same part-list legend rows (`lib::resolve_group_parts()` does the transitive member resolution for this path, independently of the parser-side resolution below). Score broadcast: `group_parser::resolve_and_validate_groups()` transitively resolves each group's members (via `group_parser::resolve_group_members()`) and rejects a group as a broadcast key (with a recoverable error, though it stays legend-eligible) when its abbreviation collides with a part's, a resolved member isn't a declared part, or its resolved members don't all share one `PartKind`; a valid `ResolvedGroup` lets `desugar::desugar_groups()` treat a `[GroupAbbrev]` score key as shorthand for writing the same line under every member's own `[Abbrev]`, with an explicit member line always taking precedence over the broadcast for that slot. Row label on unison merge: each `SourceLine` `desugar::desugar_groups()` fills from a group broadcast (and did not get overridden) is tagged with that group's abbreviation as `group: Option<String>`; this tag is threaded — unchanged through positional processing — as `per_measure_group_provenance` on `TrackAccumulator`/`ParsedTimedTrack`, onto `GroupedMeasure.group_provenance`, onto `PartSlice.group_provenance`, and finally onto `MeasureRow.group_provenance`. When the consolidator's identical-content row merge (see **Consolidator**) collapses two or more members into one row, it uses this tag to show the group's abbreviation as the merged row's label instead of concatenating member labels — but only when every merged row shares the same group tag, so a member with its own overriding line (which carries no tag) never causes a false group label. |
| **Rename-symbol support** | `src/symbols.rs`'s `collect_symbols`/`rename_edits`, consumed by editor tooling (e.g. a Monaco rename provider) to rename a part/group abbreviation or section label everywhere it's used. Reads span fields `ParsedDocument` and its sub-structures already track for this purpose: `PartDecl.abbreviation_span`, `GroupDef.abbreviation_span`/`member_spans`, `ParsedDocument.abbreviation_references` (every `[Abbrev]` key-prefix reference in `# score`), `ScoreEvent::LabelChange`'s narrowed `Spanned` span (the section-label declaration), and `SequenceEntry.label_span`/`omit_part_spans` (label and part-omission references in `# sequence`). These reference spans are kept deliberately separate from error-reporting spans that must keep their own shape — e.g. `key_span` (trimmed abbreviation only) versus `key_prefix_span` (whole `[Abbrev]` bracket, used by `RecoverableError::part_key_unknown`) in `src/desugar/mod.rs`. |
| **Sequence resolution** | `resolve_sequence()` in `src/grouper/sequence_resolution.rs`, run first inside `grouper::group()` (before `validate_navigation_markers`, which is skipped when a sequence resolves — the two schemes are mutually exclusive). Reads the parser's `ParsedDocument.sequence: Option<SequenceSection>` (from an optional `# sequence` top-level section, comma-separated section-label references) together with the `label="..."` directives already recorded per `MultiPartMeasure`, and resolves each declared label to a `SequenceSpan { label, start, end, omit_parts, omit_parts_display }` — an inclusive measure-index range running from the label's own measure to the measure before the next label (or to the last measure, for the final label), plus that occurrence's `omit_parts`/`omit_parts_display` carried over from the entry's `(-abbrev ...)` suffix. Populates `Score.sequence: Option<Vec<SequenceSpan>>`, one entry per `# sequence` reference (labels may repeat, each with its own independent omissions). Takes `declarations: &[PartDecl]` and `group: Option<&GroupSection>` (from `ParsedDocument`) to resolve each omitted abbreviation via the internal `ResolvedOmitParts { expanded, display }`: a part abbreviation resolves to itself in both; a group abbreviation expands (recursively, with a cycle guard for self-referential groups, mirroring `lib::resolve_group_parts()`) to its member parts' abbreviations in `expanded`, but is kept as the bare group abbreviation in `display` (so the group's own label, not its members, shows on the "Sequence: ..." summary line — see below). Errors (all recoverable, pushed as `Diagnostic::Error` and non-fatal to the render): using `# sequence` together with any inline navigation marker (drops the sequence, falls back to marker-based validation/expansion); declaring the same label on more than one measure (hard error, drops the sequence entirely); referencing an undefined label in `# sequence` (skips just that entry, still resolves the rest); an omission abbreviation matching no declared part or group (drops just that abbreviation, still resolves the rest of the entry). When no `# sequence` section is present, `Score.sequence` is `None` and marker-based `expand_navigation_with_origins` behavior (see **Navigation expansion**) is unchanged. `Score.sequence` is also read outside MIDI/WAV export: `build_header()` in `src/lib.rs` collects each resolved span into a `grid_layout::types::SequenceEntryInfo { label, omit_parts }` — note `SequenceEntryInfo.omit_parts` is filled from `SequenceSpan.omit_parts_display` (unexpanded), not `SequenceSpan.omit_parts` (expanded), so a group abbreviation shows as itself rather than its members — populating `Header.sequence: Option<Vec<SequenceEntryInfo>>`, and `grid_layout::layout_decoration::make_header_rows()` renders a blank gap row followed by a left-aligned "Sequence: A → B (-S -A2) → A" line — via `GridContent::SequenceLine { entries: Vec<SequenceEntryInfo> }` / `PostArcGridContent::SequenceLine` / `coordinate_resolver::content_conversion::sequence_line_content()` — on the first page only, below the title/subtitle/author/part-list rows. Each label span reuses `section_label_span()` (bold + italic, 12pt), the same styling `directive_line_content()` uses for an inline `label="..."` directive, so the two render identically; when an entry's `omit_parts` is non-empty, a plain (non-bold/non-italic) `" (-S -A2)"`-style span is appended right after its label span, so a reader sees which voices tacet on that specific repeat even though the underlying `Chorus` section is only ever rendered once, in full. The resulting spans are carried as `AbsoluteContent::DirectiveLine { label: None, spans, segno_icon_offset: None }`, reusing the existing tspan-based text renderer without its section-label background box. Reference-only — it does not reorder or duplicate measures. |

## Web integration

The React app (`web/`) runs the compiler in a dedicated worker (`web/src/worker/jianpu.worker.ts`) backed by the `jianpu-wasm` crate. The main thread sends source text and asset bytes; the worker calls WASM exports and posts structured results back.

### Storage abstraction

- Module: `web/src/storage/`
- Key types: `StorageBackend` (`web/src/storage/types.ts`) — the interface both the browser-`localStorage` backend and a future GitHub backend implement; `FileStoreState` (`web/src/fileStore.ts`) remains the canonical in-memory shape used by every backend. `StorageBackend.load`/`createFile`/`duplicateFile`/`renameFile`/`deleteFile`/`restoreFile`/`saveContent` are async (to accommodate network-backed backends); `updateActiveContent` is sync with no persistence side effect. `saveContent` is the explicit call that persists the active file's content — debounce ownership lives in the hook layer, not the backend.
- `web/src/storage/localBackend.ts` — the only `StorageBackend` implementation so far. Thin async adapter over `fileStore.ts`'s pure, synchronous functions (`createFile`, `duplicateFile`, `renameFile`, `deleteFile`, `restoreFile`, `updateActiveContent`). Its `saveContent` is a no-op since `useLocalStorage` already persists on every state change.
- `web/src/storage/githubBackend.ts` — `GithubBackend` (extends `StorageBackend`), backed by GitHub's Contents API via `Octokit`. Config (`GithubBackendConfig`): `token`, `owner`, `repo` (always the fixed `jianpu-generator-storage`, see below), optional `branch`. Files always live under the fixed `scores/` top-level folder, with deleted files moved to a sibling top-level `trash/` folder, so further top-level siblings (e.g. `metadata`) can be added without a folder picker. No sha cache (refetches immediately before each write); rename/delete/restore are two sequential Contents API calls, not one atomic commit. Exposes a non-interface `lastError(): GithubBackendError | null` (`'conflict' | 'rate-limited' | 'network' | 'unknown'`) so the settings UI can render specific banners/prompts beyond the shared `SaveStatus`.
- `web/src/storage/githubAuth.ts` — OAuth device-flow auth, via `@octokit/auth-oauth-device` with a minimal duck-typed `request` stub that routes only the two CORS-blocked device-flow calls (`POST /login/device/code`, `POST /login/oauth/access_token`) through the Cloudflare proxy (see below); everything else (Contents API, `/user`, `/repos/...`) is called directly against `api.github.com`. `connectWithDeviceFlow(options)` runs the flow to completion and persists the token; `checkGithubAuthStatus()` validates a stored token against `GET /user`; `readStoredGithubAuth()`/`clearStoredGithubAuth()` are imperative accessors (for non-component callers) and `useGithubAuthToken()` is the reactive hook equivalent (for the settings UI). Disconnecting only clears the local token — it does not revoke it on GitHub's side.
- Entry: `useStorageBackend()` in `web/src/hooks/useStorageBackend.ts` — holds the `FileStoreState` in React state and exposes `store`/`setStore`/`backend`/`saveStatus`/`preference`/`switchBackend()`/`forceSave()`/`flushPendingSave()`. `local`'s state lives in `useLocalStorage` (seeded synchronously through `localBackend`'s local-only read helpers); `github`'s state is fetched via `backend.load()` into a plain `useState` whenever the backend identity (kind/owner/token) changes. Callers `await backend.xxxFile(store)` for structural operations (create/duplicate/rename/delete/restore — hit the backend immediately), then `setStore` the result; content edits go through the existing `setStore`/`backend.updateActiveContent` path and are separately debounced (`AUTOSAVE_DEBOUNCE_MS`, ~20s, via `use-debounce`'s `useDebouncedCallback`) into a `backend.saveContent()` call — one shared cadence for both backends, immaterial for `local` (no-op `saveContent`), kept low-frequency for `github`. `switchBackend(target)` persists the choice under `jianpu:storage-backend:v1` (`{ backend, github?: { owner } }`), force-flushing (and awaiting) any pending GitHub save first, and always lands on the demo file — there is no per-backend "last active file" memory. `flushPendingSave()` similarly force-flushes a pending GitHub save without cancelling the debounce timer or switching backend; `App.tsx`'s `handleSelect` calls it before changing the active file tab, since `shouldScheduleAutosave` deliberately does not schedule a new save on such switches.
- `web/src/components/StorageSettingsModal.tsx` — the settings UI that makes the GitHub backend reachable: a Radix Dialog offering "This browser" vs. "GitHub repository", an inline device-flow connect step (rendering `githubAuth.ts`'s `onVerification` `user_code`/`verification_uri`) when GitHub is selected but not connected, and, once connected, `@username` / repo-in-use (`<repo>/scores`) / "Disconnect". Repo selection is fully automatic: `ensureStorageRepo(octokit, owner)` (exported from this file) calls `octokit.rest.repos.get()` for the fixed `jianpu-generator-storage` repo name and creates it (private) on `404` — no picker, no confirmation prompt. Also renders `githubBackend.ts`'s `lastError()` as a rate-limit/offline banner, and resolves `409` conflicts via `resolveGithubConflict()` (also exported), a minimal "overwrite mine" (retry `saveContent`) vs. "discard mine" (`backend.load()` then `updateActiveContent` with the remote content) choice — no 3-way merge. `FileList.tsx`'s `FileTabBar` exposes the entry point (a "Storage…" button plus a saving/saved/offline status badge, `onOpenStorageSettings`/`saveStatus` props); `App.tsx` owns the modal's open state and threads `backend`/`preference`/`switchBackend`/`saveStatus` from `useStorageBackend()` down to both.
- **`cf-oauth-proxy/`** — a separate Cloudflare Pages Functions project, **not** part of `web/`'s build (Vite/pnpm never sees it; it's deployed as its own Cloudflare Pages project per `cf-oauth-proxy/README.md`). It exists solely to relay the two GitHub OAuth device-flow calls that don't send CORS headers (`POST /login/device/code` → `/device/code`, `POST /login/oauth/access_token` → `/oauth/token`), injecting the OAuth App's client secret server-side; every other GitHub API call the app makes goes straight from the browser to `api.github.com`. `web/`'s build points at a deployed instance of it via the `VITE_GITHUB_OAUTH_PROXY_URL` env var (set in `.github/workflows/pages.yml`); there is no revoke/disconnect endpoint in v1.

### Split-track export

- Module: `src/split_track.rs`
- Entries: `write_split_pdfs_from_source(source, filename, base_name, tracks_filter, fonts) -> Result<Vec<SplitPdfEntry>, IrrecoverableError>` (`pdf` feature); `write_split_midis_from_source(source, filename, base_name, tracks_filter) -> Result<Vec<SplitFileEntry>, IrrecoverableError>` (`midi` feature); `write_split_wavs_from_source(source, filename, base_name, tracks_filter, sf2_bytes) -> Result<Vec<SplitFileEntry>, IrrecoverableError>` (`wav` feature)

- Backed by `parts_parser::collect_source_raw_declarations()` — returns **raw** fields from each declaration line (before `follow[X]` inheritance). The Edit Parts modal displays these values.

### Rename-symbol support (source-level)

- Module: `src/symbols.rs` (re-exported from `src/lib.rs`)
- Entries: `collect_symbols(document: &ParsedDocument) -> Vec<Symbol>`; `rename_edits(document: &ParsedDocument, kind: SymbolKind, old_name: &str, new_name: &str) -> Vec<TextEdit>`
- Key types: `SymbolKind` (`Abbreviation` — parts and groups share one namespace, so both kinds of declaration collect under it — or `SectionLabel`), `Symbol { name, kind, occurrences: Vec<SymbolOccurrence> }`, `SymbolOccurrence { span, role: OccurrenceRole }` (`Declaration` or `Reference`), `TextEdit { span, replacement }`

`generate_pdf`/`generate_split_pdfs` (`pdf` feature) follow the same pattern as the MIDI/WAV exports above: structured `{ status, ... }` envelope, `Vec<u8>` font/soundfont parameters supplied by the caller rather than embedded in the WASM binary.

`web/src/shareUrl.ts` calls `compress_share_payload`/`decompress_share_payload` directly from the main thread (a separate WASM instance from the render worker's), lazily `init()`-ing on first use, to build/parse `#share=<base64url>` links. `decodeShareHashSuffix` falls back to the legacy `lz-string`-encoded format, then plain-JSON, for links created before this switch.

Worker messages: `listParts` → `{ parts, declarations }`; `updatePartDeclaration` → `{ source, declarations }` (hook updates `partDeclarations` immediately, without waiting for the debounced re-render); `importFromFile { bytes, kind: 'svg' | 'pdf' }` → `importOk { source }` / `importErr` (`web/src/worker/importMessageHandlers.ts` calls `extract_source_from_svg`/`extract_source_from_pdf`; `useJianpuWorkerImport.ts`'s `importFromFile(file: File) -> Promise<string>` is the promise-based wrapper `App.tsx`'s Import button uses, resolved/rejected from `useJianpuWorkerMessageHandler.ts`'s `pendingImportsRef` map keyed by request id, mirroring `updatePartDeclaration`'s pending-map pattern).
